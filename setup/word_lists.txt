# setup/word_lists.txt — the word lists this program consults, in one editable place
# ===================================================================================
#
# EDIT THIS FILE BY HAND. It is meant to be edited by the people who know the
# material, not only by the people who deploy the code. Nothing here is generated
# and nothing regenerates it.
#
# EVERY LIST IS A VETO. Listing a token can stop the program calling it rubbish.
# No list here can make the program call anything rubbish. Adding a word that was
# never at risk simply does nothing, which is the safe direction to be wrong in.
#
# BUT THE SECTIONS REACH DIFFERENT DISTANCES, and that is the one thing to get
# right. Each section says below exactly what listing a token there does. If you
# are not sure which section a word belongs in, [allowed] is the one to use: it is
# the most conservative and it is the one written for this purpose.
#
# FORMAT
#   [section]        starts a section; everything after it belongs to that section
#   one token per line   — a single word, never a phrase
#   case does not matter — `Kaukasus` and `kaukasus` are the same entry
#   `#` starts a comment, on its own line or after a token
#   blank lines are ignored
#   accented characters are fine, in UTF-8
#
# PLEASE SAY WHY. Each entry should carry a short note. Two years from now the
# reason is the only thing that makes an entry safe to remove, and this issue has
# already had to undo three thresholds that were set from examples nobody wrote
# down.
#
# The path is `WORD_LISTS_PATH` in setup/config.txt. Point it elsewhere for a
# different archive, or empty it to fall back to the values compiled into
# text_util.py.


# ── [allowed] ───────────────────────────────────────────────────────────────
# WHAT IT DOES: a token listed here is not counted against the line's quality
# score. It stops contributing to the "invalid word", "weird word", "gibberish"
# and "fused word" measurements — it neither helps the score nor hurts it.
#
# AND (issue #30 Q5b, answered 2026-10-01: "yes, listed means never evidence of
# damage"): the new short-line rule's shape tests skip it, so a listed word can
# never be the reason a line is discarded. Other words on the same line are
# still judged as before.
#
# THIS IS THE SECTION FOR ORDINARY WORDS the program keeps getting wrong: place
# names, German and French museum vocabulary, Latin species names, old spellings,
# local abbreviations, anything the archive uses that a Czech word list would not
# contain.
#
# IT SHIPS EMPTY. The candidates below are real — every one is a word this issue
# has confirmed the program treats wrongly — but switching them on changes stored
# categories, so uncommenting is a deliberate, measurable act and not a default.
# Uncomment what this archive wants, then re-score and compare. Which ones to
# switch on is Q5a in issue #30; until it is answered they stay commented out.
