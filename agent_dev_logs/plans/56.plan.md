## Context
A rename looks like one setting and is three changes of different weight:
1. **The repository name** — cheap on GitHub (git, web and API URLs redirect), expensive around it: GHCR packages,
   the Pages site, the ARUP-CAS fork, SSHOMP, Galaxy and the hub's own lists do not follow.
2. **The service identity** — `/info` `service` and the spec's `x-atrium-service`. The hub's release gate treats a
   changed `x-atrium-service` as **fatal, whatever the version** (`atrium_openapi.py:417-420`), and it picks its
   baseline by asset name (`:238-283`), so the first release under the new name fails the gate unless the hub learns
   about renames first.
3. **The program id in the record** — `alto-postprocess` is an originator and a block owner in the shared contract
   (`atrium_document.py:108-280`, `atrium_vocab.py:329`). The schema's rules make a re-attributed written block a MAJOR
   bump (`docs/document_schema.md`, *Changing the schema after the freeze*); the decision of 30 September is a
   **successor map** instead (hub, *`doc-schema-v1` as the pilot baseline*), which adds a writer without re-attributing
   anything already written.

Nothing is stored at AMČR yet (report §8, risks), and S2 pins the tool versions: the window for all three is
**between the time-box release and the S2 pins**.

## Strategic actions

### A — Prepare the hub first (two small changes, one window)
1. **The gate learns about renames.** `atrium_openapi.py compare` accepts a changed `x-atrium-service` when the new spec
   declares `info.x-atrium-service-previous: "atrium-alto-postprocess"` and it equals the baseline's id; everything
   else is compared as before. One test for the accepted rename, one for an undeclared change (still fatal). The same
   rule serves any later rename; llm-enrich#29 does not need it (its service gets a new spec asset).
2. **The successor map** (with the schema round of #71/#73; proposed on the hub as *`doc-schema-v1` as the pilot
   baseline*): `ocr-postprocess` beside `alto-postprocess` in `BLOCK_OWNERS` (`pages`, `content`, `lines`, `tables`),
   `BLOCK_FIELD_OWNERS`, `ORIGIN_ORIGINATORS` (`ocr:`, `vlm:`, `ABBYY-ALTO`) and `LINE_CATEGORY_ORIGINATORS`;
   `PROGRAM_SUCCESSORS = {"alto-postprocess": "ocr-postprocess", …}` used by the origin check, the field grants and the
   merge, never to rewrite a stamp. Records written before keep `alto-postprocess` in `assembled.blocks`; both names are
   accepted on read. RO-Crate tool ids become release URLs of the new name (#71 B3); old URLs redirect.
3. **Re-vendor, move `v1`** — the tool repositories pick both up before this repository changes a single string.

### B — Rename, in one window
1. **After** the time-box release (1.7.0-beta), so its fixes and the rename are not in one diff.
2. **GitHub**: rename the repository. **Never** create a new repository under the old name: that silently ends the
   redirects.
3. **This repository**, one commit:
   - `SERVICE = "atrium-ocr-postprocess"`; the committed spec regenerated with `x-atrium-service-previous`;
   - `PROGRAM_NAME = "ocr-postprocess"` (`document_hook.py:43`) and the six `program=` call sites
     (`extract_ALTO_2_TXT.py:167`, `extract_JSON_2_TXT.py:226`, `extract_LytRdr_ALTO_2_TXT.py:415`,
     `extract_LLM_ALTO_2_TXT.py:211`, `text_stats_create.py:163`, and the lookup at `text_util.py:91`);
   - images `ghcr.io/ufal/atrium-ocr-postprocess` and `…-api` (`docker.yml:38`, `security.yml:42`,
     `docker-compose.yml:3,14,18,42`), `ATRIUM_RUNNER_IMAGE` with them;
   - `CITATION.cff` (title, `repository-code`, keywords), README (title, badges, image names, introduction), the
     `gh-pages` site (its URL changes: GitHub does not redirect Pages);
   - tests that pin the old names (the originator and vocabulary tests are vendored from the hub and change there).
4. **The first release under the new name** is **2.0.0-beta**: the program id in every record it writes changes,
   which readers keyed on `assembled.blocks[…].program` will see; a major bump says so even though the successor map
   keeps it compatible.

### C — Say what the tool now is, keep what it does
1. **README and docs**: the title becomes an OCR-and-text postprocessor; the input section leads with the families it
   reads — OCR output (ALTO, PAGE XML, hOCR, ABBYY, JSON) and text-bearing files (`docs/text_inputs.md`, #31) — and the
   ALTO path stays the worked example, since it is the PSNC corpus.
2. **Script and module names stay** (`extract_ALTO_2_TXT.py`, `alto_stats_create.py`, `alto_tools.py`, …): they name
   steps that really are ALTO-specific, and renaming them would break every runbook, E2E step and paradata component
   name for no behavioural gain. The issue asks to preserve the pipeline; this is where that applies.
3. **Categories, calibration and scoring**: untouched (#2, #3, #4, #30 are time-boxed and frozen for the S2 pilot).

### D — The boundary with the born-digital converter
Both repositories read DOCX, ODT, RTF and spreadsheets (`text_formats.py`; llm-enrich#10 §12 W2). The split of work:
- **In the AMČR chain**, a born-digital file goes to the converter (dbc, llm-enrich#29), which originates the record;
  `text_formats.py` already marks such inputs with a `digital-born-*` origin, so this repository writes only `source`
  for them and never their plane.
- **This repository owns the readers**; dbc vendors them with SHA pins (the pattern of llm-enrich's
  `tests/test_vendored_teitok_parity.py`) — the "one document reader" of hub #72.
- **This repository scores** born-digital lines (llm-enrich#10 W3) and merges AMČR's OCR of `needs_ocr` pages into the
  converter's record (W4). Neither needs the positional plane of a born-digital page.
- **Its CLI** keeps reading every text-bearing format, for batch use outside the AMČR chain.

## Verification / done-criteria
1. `git clone https://github.com/ufal/atrium-alto-postprocess` still works (redirect); the new URL is canonical.
2. The release gate passes 2.0.0-beta against 1.7.0-beta with `x-atrium-service-previous`, and still fails a spec whose
   service id changed without it (the hub test of A.1).
3. A record written by 2.0.0-beta carries `ocr-postprocess` in `assembled.blocks`; a record written by 1.7.0-beta still
   loads, merges and passes the origin check (hub test of A.2).
4. The hub E2E pipeline smoke is green against `ghcr.io/ufal/atrium-ocr-postprocess:2.0.0-beta`.
5. `grep -rn "atrium-alto-postprocess"` in this repository returns only history (changelog, DEVLOG, digests) and the
   note on old image names.
